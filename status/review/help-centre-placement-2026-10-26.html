Help centre placement: app host or website (R285-WEB-HELP-CENTRE-01)

Date 2026-10-26. Research only, no code changed. Every choice below is a question for the owner.

1. Owner question

staging-app.velstrian.com/help works signed out and signed in. Why is it not on the website, like other enterprise SaaS? Answer: there is no good reason it lives on the app host. It was moved out of the login-gated dashboard in 2026-05 (BUG-005) so crawlers and anonymous visitors could read it, and it stayed on the app because that was the nearest public route.

Pattern: all four put knowledge on a separate public help subdomain, not on the app host. None sits behind login. The app only holds a thin link or a contextual widget, and anything that needs the customer's data (cases, account) stays behind login. I did not verify each vendor's robots or sitemap, so the SEO column is limited to what the pages showed.

4. Recommended model (one option, owner decides)

Public help centre on the website at velstrian.com/help, one source of content, a thin in-app link layer.

Why path not subdomain: the website is one Cloudflare Pages project, a path costs no new DNS, no new project and no new certificate, and the Astro build, search index and sitemap already exist there. A help. subdomain adds a second Pages project for no gain at our size. This matches the vendor pattern in spirit (separate public knowledge surface) while staying on Cloudflare Free.

What moves to the website:

  • The 39 articles, /help index, article pages, and /help/contact (public form, posts to the existing /api/contact/submit on the app API, so the form stays working, only its page moves). Needs a cross-origin allow-list check, a lane task.
  • Videos (/videos/onboarding/*) served from the website.
  • Legal pages (legal)/accessibility is a duplicate and can redirect, DPA, sub-processors, residency, retention, refund policy are public legal text and belong on the website with the existing legal/ collection. Owner question, not done here.
  • /pricing public entry on the app host should redirect to the website.

What stays in the app:

  • The contextual "Guide for this page" link (kept, now points to https://velstrian.com/help/<slug>), sidebar item (opens website), CrowChat Help tab (keeps its in-app search, links out to articles).
  • /status (reads live incident data), /respond/[token], /sign/[token], /supplier/, /docs/test-mode, /changelog.xml feed.
  • /support and /knowledge-base dashboard pages (need the customer's data and tickets).

Single source of content: keep one file of articles and generate both outputs from it. Recommended: move the article source into the shared @velstrian/tokens-style workspace package or a JSON export produced by the platform build and committed into the website (Astro content collection). The governed figures (prices, seats, credits, PPN thresholds) currently resolve inside the TypeScript file at build, so the export must be built from that file, not hand-copied, or the RULE 0-C price guard is lost. The AI help (/api/chat/public and CrowChat articles.ts) keeps reading the same file. The website copy is a generated artefact with a guard test that fails if it drifts.

Redirects: app /help and /help/:slug return 308 to https://velstrian.com/help/:slug (one rule in web/proxy.ts or next.config.mjs). Remove /help from the app sitemap and PUBLIC lists after the redirect lands. /help/contact redirects too. Trial wall exemption becomes moot.

Effect on go-live (A-450): the website go-live does not need this. It can ship first without /help, because the app /help keeps working. Order if the owner agrees: (1) website ships, (2) help centre section built on the website and walked locally, (3) platform cutover adds the redirects and rewrites in-app links. Folding it into A-450 widens that push (a new section on a site about 300 commits ahead of live), so the recommendation is a follow-up push with its own approval and cost statement, not part of A-450. Effect on platform cutover: one proxy redirect rule plus link constants, and help-links.ts plus contextual-help.ts need a base URL constant (RULE 0-C, no hard-coded host).

Cost: GBP 0 recurring. Website is Cloudflare Pages on the Free plan, no help desk product, no new project, no cron, no CI workflow. One push to the website (explicit owner approval, RULE 0-G) and one platform promote.

Size estimate (lanes and files):

  • Lane A (builder): export script plus Astro help route (index, article, search via existing search-index), 3 pages or components, 1 generated data file, 1 drift guard test. About 8 files.
  • Lane B (builder): app side. Redirect rule, base URL constant, 6 to 8 in-app link files, sitemap, route-classification, trial-wall, tests updated. About 14 files.
  • Lane C (researcher or mechanic): diff faq.astro against help articles and remove duplicates, move legal pages decided by the owner. About 6 files. Total 3 lanes, about 28 files.

  1. Where does public help live? Options: (a) velstrian.com/help on the website, recommended, (b) help.velstrian.com second Pages project, (c) leave on the app host and only add noindex or links.
  2. Include it in the A-450 push or ship it as its own later push? Recommended: later, own approval.
  3. Move the public legal pages (DPA, sub-processors, residency, retention, refund) to the website too? Recommended: yes, same lane, separate sub-decision per document if counsel prefers to review.
  4. Single source mechanism: generated export from the platform article file. Recommended over hand-copying.
  5. /help/contact form: keep posting to the app API from the website page. Recommended, avoids a new backend.
