  • The name is NOT centralised. Colour is (one brand.source.json for both repos). The wordmark, the legal line and two logo components are still hard coded. The first work package therefore builds one identity block, then a codemod, then a guard test.

Section 2Decisions the owner must make

Each decision is a question with options and one recommended answer. None is settled by this page.

D1. Is Velstran the final name, subject to clearance?

  1. Go only if the register clearance and an attorney review are clean (Gate 0)
  2. Go now and accept the risk
  3. Pick another name

Recommended: Option 1. A second opposed application would cost another cycle, and clearance costs far less than that.

D2. CrowMark and CrowMark Buyer both contain the stem Crow. Rename them too?

  1. Keep both names for now
  2. Rename both in this same programme (needs two new names cleared)
  3. Keep for now and decide after the CrowAgent opposition grounds are read

Recommended: Option 3. Read who opposed and on which element first. If the grounds cite the Crow stem, take option 2 inside this programme, because a second rebrand later costs more than extending this one by about 2 sessions. This is the owner decision, the recommendation is not a ruling.

D3. Which domains to buy and where?

  1. velstran.com, velstran.co.uk, velstran.uk at Porkbun (USD 22.40 year one)
  2. Add velstran.ai (USD 82.70 a year) and velstran.app
  3. Different registrar

Recommended: Option 1. Porkbun is the only registrar whose first-year and renewal prices were verified here. DNS stays on the free Cloudflare plan, never Cloudflare Registrar.

D4. Primary public domain

  1. velstran.com with app.velstran.com and portal.velstran.com
  2. velstran.co.uk
  3. velstran.ai

Recommended: Option 1. The two UK domains redirect to it.

D5. Trade mark route

  1. Standard UK online application, GBP 205 plus GBP 60 per extra class
  2. UK Right Start check first
  3. UK plus EU and WIPO filings now

Recommended: Option 1 with an attorney reviewing the specification. Add EU or WIPO only after the UK path is clear. Classes 9, 35 and 42 are an assumption to confirm with the attorney.

D6. Order of company name change versus trade mark filing

  1. File the trade mark first, then change the company name
  2. Change the company name first
  3. Same week

Recommended: Option 1. Filing fixes the date. The name change is a same-day online filing.

D7. What happens to the opposed CrowAgent application?

  1. Let counsel advise on withdrawing, defending or letting it lapse
  2. Withdraw now
  3. Defend

Recommended: Option 1. This is procedure and money that only the owner and a trade mark attorney can decide.

D8. Internal identifiers: package scope @crowagent/*, CROWAGENT_ env vars, database names, Stripe lookup keys, repo and project names

  1. Keep all internal, change everything a customer can see
  2. Rename internals too

Recommended: Option 1. Renaming internals touches secrets in four vendors and lockfiles for no customer value. A later optional cleanup can follow.

D9. Cutover shape

  1. Run both domains in parallel for 30 to 90 days, then retire the old ones to redirect only
  2. Hard cutover on one day

Recommended: Option 1. Passkeys, OAuth redirect URIs and email reputation all need an overlap.

D10. The platform mailbox crowagent.platform@gmail.com and the identity rule in CLAUDE.md

  1. Create a new platform identity and restate the rule myself
  2. Keep the mailbox as an internal identity

Recommended: Option 2 for now. The rule names this identity and only the owner can change it. A Gmail address cannot be renamed (UNVERIFIED here), so a new mailbox plus forwarding is the route if wanted.

D11. Owner supplied artwork

  1. Owner provides the Velstran mark, wordmark and favicon
  2. Claude proposes concepts

Recommended: Option 1. RULE 0-C forbids inventing a brand value. Colours stay frozen per the owner decision of 2026-08-11.

D12. Push and deploy budget for this programme (RULE 0-G, RULE 0-P)

  1. 2 pushes (platform, website) and 1 production promote of web and portal, each with its own approval
  2. More

Recommended: Option 1. Staging promote needs no push. Costs are stated again before each ask.

Product names: CrowMark and CrowMark Buyer

CrowMark and CrowMark Buyer both contain Crow. The CrowAgent application was opposed, but the grounds are not known to this research. If the opposer relied on the Crow element, the CrowMark names carry the same exposure and renaming only the company would move the problem instead of removing it. If the opposer relied on Agent or on a descriptive overlap, CrowMark may be unaffected.

  • A. Keep both names (cheapest, exposure unknown)
  • B. Rename both inside this programme (needs two cleared names, about 2 extra sessions, 12 lane hours, 5M tokens, and a second clearance)
  • C. Keep for now, decide at Gate 0 after the grounds are read

Recommendation as a question: choose C, then B if the grounds cite the Crow element. A later second rebrand would repeat the whole sweep, whereas doing it now adds about 30 percent. The owner decides.

How central the name really is (RULE 0-C)

  • Colour: central. packages/tokens/brand/brand.source.json is the one source, gen-brand.mjs writes tokens.css, constants.ts and the copy in crowagent-website/astro/src/styles (package.json brand comment, packages/tokens).
  • Contact identity: central. packages/tokens/src/contact.ts holds SUPPORT_EMAIL, SALES_EMAIL, SECURITY_EMAIL and the From name. attribution.ts holds the document footer. Both are imported through @crowagent/tokens, which has 44 import lines across web and apps.
  • Wordmark and legal line: NOT central. email-shell.ts lines 124 to 140 hard code the text CrowAgent and the company line. No BRAND_NAME or COMPANY_NAME constant exists in web/src (grep for the usual names finds only two unrelated i18n files).
  • Logo: duplicated. CrowAgentLogo.tsx exists in web/src/shared/ui and apps/portal/src/components.
  • Python side: partly generated. api/app/services/_email_shell_generated.py and regulated_constants_generated.py show a generator pattern that can be extended, but api/app/config.py hard codes the addresses and the default sender display name.
  • Website: astro/src/data/site.ts holds 15 hits and pages repeat the name directly. The website keeps its own copy of brand.source.json.
  • Verdict: change once and propagate is true for colour and half true for contact. It is false for the name. Plan WP3.1 first and make everything else consume it.

Guard test design

  • Add an identity block to brand.source.json (name, legalName, formerName, primary domain, hosts, mailbox addresses) and make gen-brand.mjs emit it for TypeScript, Python and astro. brand:check already fails on drift.
  • Guard test: scan the code roots (web/src, apps/portal/src, api/app, packages, astro/src) with comments stripped for crowagent, Crow Agent and CrowAgent, case insensitive. Fail on any hit outside an allowlist of patterns, not a count.
  • Allowlist patterns: the @crowagent/ package scope, CROWAGENT_ env names, crowagent_<product>_ Stripe keys, the supabase/migrations tree, the redirect map file, the formerly known as legal line, localStorage keys, and test fixtures that assert the absence of the old name.
  • Red prove it: add a raw old name to a component, show the test fail, remove it. Run it locally through pnpm. Per RULE 0-G it is attached to the product fix in the same commit, it is a pattern allowlist and not a numeric baseline, and wiring it into CI needs separate owner approval.
