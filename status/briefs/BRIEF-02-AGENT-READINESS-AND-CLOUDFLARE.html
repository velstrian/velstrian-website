  2. At build time emit a Markdown twin of every public HTML page (/pricing gets /pricing.md, / gets /index.md). Change 2, rate limiting rule (auth endpoints on app.velstrian.com)

The Cloudflare agent asked for paths on api.velstrian.com. There are none. The driver measured the code on 2026-10-30: the API has no sign in or password reset endpoint. Password sign in goes from the browser straight to Supabase (which has its own limits and Turnstile). The account recovery endpoints live on the web app, app.velstrian.com, which is proxied by Cloudflare.

Security, Security rules, Create rule, Rate limiting rule.

  • Name: Rate limit account recovery endpoints
  • Expression: (http.host eq "app.velstrian.com" and (starts_with(http.request.uri.path, "/api/auth/password-reset/") or http.request.uri.path eq "/api/auth/reset-password" or http.request.uri.path eq "/api/auth/unlock" or http.request.uri.path eq "/api/auth/accept-invite" or starts_with(http.request.uri.path, "/api/auth/email-change")))
  • Characteristic: IP. Period 10 seconds. Requests: 20. Action: Block. Duration: 10 seconds (the free plan fixes these, take what it allows and report it).
  • Must NOT match /api/auth/send-email-hook (Supabase calls it from a few shared IPs, blocking it stops every auth email), /auth/callback, any Stripe or webhook path, or anything on api.velstrian.com. The expression above already avoids them, do not widen it.
  • The free plan allows one rate limiting rule. If one already exists, stop and report it.

Test: one curl -s -o /dev/null -w "%{http_code}" -X POST https://app.velstrian.com/api/auth/password-reset/request -H "Content-Type: application/json" -d "{}" returns the same status as before the rule (a 4xx for an empty body is fine). Do NOT send 20 requests to trip it, and never put a real email address in the body.
