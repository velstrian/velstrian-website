Part A, mono labels at weight 500

The technical font is DM Mono (packages/tokens/src/constants.ts:155, packages/tokens/src/tokens.css:474). DM Mono has no 700 weight, so every mono label set to bold is a FAKE bold the browser draws. Driver decision (no scope change): mono labels use weight 500.

  1. Find every place mono text is set bold or 700: Tailwind font-mono together with font-bold or font-semibold (about 48 class lists across web/, apps/portal/src, packages/), and CSS rules that use var(--font-mono) or var(--ca-font-mono) with font-weight: 600 or 700. Strip comments before counting. Report the count per area.
  2. Fix it centrally. Add a token for the mono label weight (for example --font-mono-weight: 500 in tokens.css, mirrored in constants.ts if constants carry weights) and a utility class or Tailwind theme entry that sets mono and that weight together. Point every place from step 1 at it. Do not leave a raw 500 in components.
  3. Check the font files load 500. If only 400 is loaded, load DM Mono 500 the same way 400 is loaded (self hosted, no external font host). Report which weights are now loaded.
  4. Add a guard test that fails if font-mono appears with font-bold or font-semibold, or a mono rule sets weight 600 or 700, comments stripped. Prove it red on the old tree, green after.
  5. Emails and PDFs: if the email shell or PDF styles use mono at 700, change them through their own token source (packages/tokens/src/email-shell.ts and the PDF style source), then regenerate the generated files with their own generator scripts (api/app/services/_email_shell_generated.py, scripts/generate-auth-email-templates.mjs). Never hand edit a generated file.

Part B, dark theme teal text from #FFFFFF to #F8F9FB

Driver decision 2026-10-29 (no scope change): in the dark theme, the primary text colour used on teal changes from pure white #FFFFFF to #F8F9FB, in the central tokens, website included.

  1. Find the token that holds that colour in packages/tokens/src/tokens.css (and its source, for example brand.source.json, if tokens are generated). Read the comments around it first. If a comment warns against this change, stop and report it.
  2. Change it once at the source and regenerate whatever is generated from it. Report every token name that changed and every generated file that changed.
  3. Website: velstrian-website takes its tokens from the same source or a synced copy. Find how it gets them and apply the same change through that path, never by hand editing a colour.
  4. Contrast: compute the contrast ratio of the new colour against every dark theme teal background it sits on (read the background tokens). Each must stay at or above 4.5 to 1 for normal text. Report the numbers.
