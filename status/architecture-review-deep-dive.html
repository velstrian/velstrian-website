The Defensible Decision Record

web/src/features/public-sector/decision-record.ts. Three mechanisms, each designed against a specific way an evaluation is later challenged.

Weights are locked before any evidence is seen. A SHA-256 hash over a canonical payload of the weightings, criteria and scoring bands, timestamped, and checkable afterwards. Numbers are fixed to four decimal places with negative zero normalised, and strings are JSON-encoded so a separator character in a criterion name cannot forge a field boundary. Band order is preserved because band resolution is first-match. If SHA-256 is unavailable the lock reports UNAVAILABLE rather than falling back to a home-rolled digest, which is the right failure.

A provenance ladder of six classes from contractual down to third-party commentary. A class can be weakened but never promoted, document-backed classes cannot be claimed without the document, and an unrecognised class is rejected rather than silently mapped to the weakest.

Three missing-evidence states that never collapse into one: evidenced, asserted_not_evidenced and not_addressed. “Absent” and “present but weak” are different facts, and a sensitivity check says which gaps can change the ranking and which the buyer should stop chasing.

The understatement runs the other way, and the file says so itself. Only the weight lock has user-visible behaviour.
